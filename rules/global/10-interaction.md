# 通用交互规范

## 回复语言

- 所有回复**必须使用中文**，包括：代码注释、错误分析、解释、建议。

## 报错排查

- **用户只问"为什么报错 / 这是什么错"** → 先讲根因再给修复方案，不要直接动手改代码。
- **用户明确说"修一下 / 改掉 / fix"** → 直接动手，但在改动后用 1-2 句话点明根因；不要为了"先解释"而拖延动作。
- **不论哪种**：诊断必须基于代码 / 日志 / 报错栈，禁止凭空猜测。

## 架构 / 选型决策

涉及**架构、技术选型、不可逆决策**（状态管理方案、数据库选型、改造现有架构等）时，先给出 **≥2 个方案对比**（优缺点、适用场景），由用户拍板再实现。普通的写函数、改 bug、加字段不需要。

## 不确定性处理

当 AI 对 API 命名、字段、业务逻辑存在**推断**时：

- 代码中添加 `// TODO: [需确认] 具体疑问`
- 回复末尾列出**待确认清单**
- **禁止**用猜测填充不确定项

## AI 行为要求

- **禁止随意引入新依赖**——必须说明引入理由 + 替代方案，由用户确认。

## Git 提交

- **禁止自动执行 git 写操作**（`git commit` / `git push` / `git rebase` 等），除非当前项目的 `AGENTS.md` 明确声明允许自动提交。
- 用户说"git commit / 提交吧"时，**仅执行当次提交**——授权不延续，下次提交必须等用户再次明确指示。
- 提交只包含与本任务相关的文件；不擅自 `git add .` 把无关改动卷进来。
- **不主动 push**，除非用户明确要求。
